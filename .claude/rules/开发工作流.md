# 开发工作流规则（强制执行）

## 6 段固定结构（每轮必须输出）

1. **本轮任务理解（≤5行）** - 只做什么 / 不做什么
2. **变更计划 & 文件列表** - 白名单 + 禁止项
3. **实现内容（按文件分段）** - 补丁风格说明
4. **验证步骤** - 目录 + 命令 + 预期输出
5. **风险点 & 自检清单** - 影响 + 风险 + 回滚方式
6. **回滚方案** - 具体步骤

---

## 原子任务粒度

一个原子任务 = 一个接口 / 一个脚本 / 一个页面

**禁止同时动：**
- 多个模块（如 wallet + stake + trading）
- 前后端一起大改
- 重构 + 改业务

---

## 反死循环机制

连续 2 轮失败 → 自动进入反死循环模式：

1. **冻结范围** - 只改一个文件/函数
2. **写清复现步骤** - Given/When/Then
3. **最小修复** - 只改最可能的一个点
4. **最小自测** - 只针对这个点验证

---

## 提交规范

### 小步提交
- 单次提交 ≤ 5 个文件
- 每个变更配：自检清单 + 回滚步骤

### 提交信息格式
```
[类型] 简短描述（≤50字符）

详细说明:
- 改了什么
- 为什么改
- 影响范围
- 如何验证
- 如何回滚
```

类型：
- `[feat]` 新功能
- `[fix]` 修复 bug
- `[docs]` 文档更新
- `[refactor]` 重构
- `[test]` 测试
- `[chore]` 杂项
