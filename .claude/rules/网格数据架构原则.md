# 网格策略数据架构原则（不得修改）

> 版本：v1.0 | 锁定日期：2026-03-11
> **违反以下原则的任何改动 = 交付不合格，必须打回**

---

## 核心原则：交易所数据是唯一事实

```
AI 每轮拿到的数据 = 交易所实时数据（CCXT API）
内存 state = 运行时索引（orderId→层映射），绝非权威数据源
DB 持久化 = 崩溃恢复用，启动后立即被交易所数据覆盖
```

**任何"以内存/DB 为准"的逻辑都是错误设计，必须删除。**

---

## 数据流（每个运行周期，与 nofx 完全一致）

```
每轮周期
  ↓
buildGridContext()
  ├── adapter.getBalance()          ← 实时余额（fresh，每轮调用）
  ├── adapter.getPositions()        ← 实时持仓（fresh，每轮调用）
  ├── adapter.getOpenOrders()       ← 实时委托（fresh，每轮调用）
  ├── fetchOHLCV(5m/1h/4h)         ← 实时K线（fresh，每轮调用）
  └── ctx.levels ← state.gridLines  ← 内存索引（仅用于orderId→层号映射）
  ↓
AI LLM 决策（基于 ctx，即交易所实时数据）
  ↓
执行 AI 指令（下单/平仓/重建）
  ↓
syncOrderFills()                   ← 增量更新内存索引（orderId消失→判断成交）
```

**关键**：AI 看到的 `currentPosition`、`positionLong`、`positionShort`、`exchangeOpenOrders` 全部来自交易所实时 API，不是内存。

---

## 内存（state.gridLines）的唯一用途

内存只做一件事：**orderId → 层号 映射**

因为交易所成交通知只返回 orderId，没有层号，必须靠内存查找对应层。
这与 nofx 完全一致（nofx 同样用内存维护 orderId→层 映射）。

**内存不是持仓真相，不是委托真相，只是索引。**

---

## 启动恢复原则（reconcileGridState）

**禁止**从 DB 恢复的历史层状态直接使用。

启动流程（三步，不得增加）：
1. **全部重置**：所有层 → empty，清除所有历史状态
2. **从交易所委托单恢复 pending**：getOpenOrders() → 按价格最近匹配层
3. **从交易所持仓恢复 filled**：getPositions() → 按入场价最近匹配层

```
DB 状态 → 全部丢弃 → 以交易所为准重建
```

---

## 网格重建原则（reinitializeGridLevels）

重建时：
1. 保存当前内存中的 filled 持仓快照（positionEntry/positionSize/side）
2. 重置所有层为 empty
3. 将快照按入场价最近原则映射到新层

**注意**：快照来自内存，但只保留持仓的数量和价格，不保留层号。
新层号由价格距离决定，始终以当前价格为参考重新分配。

---

## 严禁以下模式

| 禁止 | 原因 |
|------|------|
| 在 buildGridContext 内做持仓对账 | 每轮运行，API 失败会清除真实 filled |
| 用 DB 层状态直接作为运行状态 | DB 是历史快照，可能与交易所不一致 |
| "幽灵层"清理逻辑 | 根本不应该存在幽灵，启动时重建即可 |
| "孤儿持仓"映射逻辑 | 启动三步流程已覆盖，无需单独处理 |
| 内存量 vs 交易所量的阈值对账 | 来源单一（交易所），无需比较 |
| 部分匹配/多余清除等复杂逻辑 | 全部重置比部分对账更安全更简单 |
