# 交付物标准规则

> 对应通用规则：第 4 章上线最低标准、第 7 章通用交付物

---

## 4. 上线可运行最低标准

任何可对外访问的服务/脚本/自动化必须具备：

| # | 标准 | 说明 |
|---|------|------|
| 1 | **健康检查可用** | `/api/health` 或等价的自检接口 |
| 2 | **关键错误日志可定位** | 含 `request_id` 或 `trace_id` |
| 3 | **关键配置环境变量化** | 禁止硬编码密钥 |
| 4 | **失败有明确兜底** | 超时/重试/错误提示/降级 |
| 5 | **关键路径有最小测试** | 至少 3 用例（正常/异常/边界） |
| 6 | **明确回滚方案** | 能回到上一个稳定版本 |

## 7.1 通用交付物目录（建议）

不强制建目录，但 AI 每轮交付必须对应输出这些内容：

```
01_需求/     MVP 冻结、不做清单、验收标准（Given/When/Then）
02_原型/     页面清单、流转图、关键交互、空/错/加载态
03_数据/     数据表（字段/类型/约束）、权限矩阵、审计字段
04_API/      接口合同（入参/出参/错误码/示例）、第三方集成
05_实现/     代码/低代码配置/环境变量表
06_测试/     冒烟清单、回归清单、已知问题列表
07_部署/     部署步骤、监控告警、备份恢复、回滚说明
CHANGELOG.md 每轮变更记录（改了什么/风险/验证/回滚）
```

---

## 7.2 可复用组件交付规范

当 AI 提议"抽组件/做复用模块"时，组件交付必须包含：

1. **组件代码与资源目录**
2. **README 文档**：
   - 引用路径
   - 依赖版本
   - 使用示例
   - 常见坑（尤其路径与环境）
3. **最小 Demo 或验收方式**（可独立验证组件可用）

---

## 7.3 文档即代码（README.md / DEV_Log.md）

项目必须至少维护其一：

| 文档 | 用途 |
|------|------|
| `README.md` | 面向新加入者，描述项目目标、启动方式、目录结构 |
| `DEV_Log.md` | 按时间记录每次关键变更 |

### 强制要求

任何配置/依赖/启动方式变更，必须同步更新文档，包含：

- **变更内容**（新增/修改/删除）
- **生效范围与影响**
- **验证方式**（命令 + 预期输出）
- **回滚方式**

## 每轮交付检查清单

AI 在每轮交付前，必须自检：

- [ ] 功能可验收（有肉眼可见成功信号）
- [ ] 有验收步骤（命令 + 目录 + 预期输出）
- [ ] 有回滚方案
- [ ] 涉及配置变更已更新文档
- [ ] 关键路径有测试用例
- [ ] 日志可定位（有 request_id）
