# 上下文记录规则

> 目的：保持开发节奏，确保跨会话的上下文延续性

---

## 会话开始时

每次新会话开始，AI 必须：

1. 读取 `文档/核心文档/开发顺序.md` 确定当前阶段
2. 检查最近的夜间日志（如有）
3. 输出当前开发状态摘要

```
## 当前开发状态

### 所处阶段
Phase X: [阶段名称]

### 已完成
- [x] 任务1
- [x] 任务2

### 进行中
- [ ] 任务3 - [进度说明]

### 待开始
- [ ] 任务4
```

---

## 任务执行中

### 使用 TodoWrite
- 跟踪每个原子任务的进度
- 任务状态：pending → in_progress → completed
- 同一时间只有一个任务 in_progress

### 记录重要决策
- 技术选型理由
- 问题解决方案
- PM 的决定

### 阻塞时立即记录
- 问题描述
- 已尝试方案
- 需要 PM 决定的事项

---

## 任务结束时

### 更新开发顺序文档
- 勾选已完成项
- 更新进度百分比

### 输出交接摘要
```
## 本轮交接摘要

### 已完成
- [任务1]
- [任务2]

### 未完成
- [任务3] - 原因：xxx

### 下次需要做
1. [具体任务]
2. [具体任务]

### 注意事项
- [需要关注的问题]
```

---

## 跨会话恢复触发词

当用户说以下话时，自动恢复上下文：

- "继续" / "接着做"
- "上次做到哪了"
- "恢复开发"
- "现在做到哪一步了"

恢复时输出：
1. 当前阶段
2. 最后完成的任务
3. 下一步计划
