# 夜间工作模式规则

## 触发词

- "今晚帮我做..."
- "夜间任务..."
- "明早验收..."

---

## 核心原则

夜间模式 = 打包执行 + 不中断 + 详细日志

---

## 任务执行规则

### 允许
- 只做明确列出的任务
- 遇到问题自己解决或跳过
- 生成详细日志

### 禁止
- 修改架构
- 引入新依赖
- git push
- 删除文件/表
- 修改 .env

---

## 安全限制

| 限制项 | 阈值 |
|-------|------|
| 单任务最多改文件数 | 5 个 |
| 单文件最多改行数 | 200 行 |
| 同一任务最多尝试次数 | 2 次 |
| 单任务最长执行时间 | 2 小时 |

超过限制 → 停止 → 记录 → 等待晨间审核

---

## 日志位置

`文档/夜间日志/YYYY-MM-DD-任务简述.md`

---

## 日志模板

```markdown
# 夜间开发报告 - [任务简述]

**执行日期**: YYYY-MM-DD
**任务状态**: SUCCESS / FAILED / TIMEOUT / STUCK

## 1. 任务概述
- 任务 ID：
- 开始时间：
- 结束时间：

## 2. 执行摘要
- 修改的文件列表
- 执行的命令

## 3. 验证结果
- 编译：通过/失败
- Lint：通过/失败
- 测试：X passed / X failed

## 4. 问题与风险
- 遇到的问题
- 需要 PM 关注的事项

## 5. 晨间验收清单
- [ ] 验收步骤1
- [ ] 验收步骤2

## 6. 回滚方案
- 如何回滚：`git revert xxx`
```

---

## 晨间审核流程

PM 早上起来后：

1. 查看 `文档/夜间日志/` 最新文件
2. 检查任务状态
3. 执行验收清单
4. 决定：合并 / 回滚 / 继续修复
