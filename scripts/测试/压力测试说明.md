# QuantFi 压力测试指南

## 1. 安装 k6

### macOS

```bash
brew install k6
```

### Linux

```bash
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

### Docker

```bash
docker run --rm -i grafana/k6 run - <script.js
```

## 2. 运行测试

### 基本运行

```bash
cd /Users/azu/主QuantFi
k6 run scripts/测试/压力测试.js
```

### 指定 API 地址

```bash
k6 run -e API_URL=http://api.quantfi.io/api scripts/测试/压力测试.js
```

### 调整并发数

```bash
# 使用环境变量覆盖配置
k6 run --vus 200 --duration 5m scripts/测试/压力测试.js
```

### 输出报告

```bash
# HTML 报告（需要 k6 扩展）
k6 run --out json=result.json scripts/测试/压力测试.js

# 实时 InfluxDB（可接入 Grafana）
k6 run --out influxdb=http://localhost:8086/k6 scripts/测试/压力测试.js
```

## 3. 测试场景

### 场景 1: 冒烟测试（快速验证）

```bash
k6 run --vus 5 --duration 30s scripts/测试/压力测试.js
```

### 场景 2: 负载测试（正常负载）

```bash
k6 run --vus 50 --duration 5m scripts/测试/压力测试.js
```

### 场景 3: 压力测试（高负载）

```bash
k6 run --vus 200 --duration 10m scripts/测试/压力测试.js
```

### 场景 4: 峰值测试（突发流量）

```bash
k6 run --vus 500 --duration 2m scripts/测试/压力测试.js
```

## 4. 性能指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| http_req_duration | 请求响应时间 | P95 < 2s |
| http_req_failed | 请求失败率 | < 5% |
| http_reqs | 每秒请求数 | > 100 RPS |
| vus | 虚拟用户数 | 根据场景 |

## 6. 故障排查

### 高错误率

- 检查服务器资源（CPU/内存/磁盘）
- 检查数据库连接池
- 检查 Nginx 限流配置

### 高响应时间

- 检查慢查询
- 优化数据库索引
- 增加缓存

### 请求超时

- 增加服务器超时配置
- 检查网络延迟
- 优化 API 逻辑

## 7. 生产环境建议

1. **在非高峰期运行压力测试**
2. **先在预发布环境测试**
3. **监控服务器指标**
4. **准备回滚方案**
5. **设置合理的并发上限**
