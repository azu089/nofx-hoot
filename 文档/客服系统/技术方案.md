## 二、关键选型决策

### 2.1 Bot 框架：复用现有 grammY Bot

| 方案 | 优劣 | 决策 |
|------|------|------|
| 复用现有 Bot | 无需新建 Bot、用户无感、复用认证逻辑 | ✅ 选这个 |
| 新建独立客服 Bot | 职责分离但用户需关注两个 Bot | ❌ 不采用 |

**改造点**：`bot.on('message:text')` 处理器从"回复未知命令"改为"AI 客服问答"。

### 2.2 LLM 模型

| 模型 | 成本 (input/output per 1M tokens) | 速度 | 质量 | 决策 |
|------|-----------------------------------|------|------|------|
| GPT-4o-mini | $0.15 / $0.60 | 1-2s | 够用 | ✅ 首选 |
| Claude 3.5 Haiku | $0.25 / $1.25 | 1-2s | 略好 | 备选 |
| DeepSeek V3 | $0.27 / $1.10 | 2-3s | 够用 | 备选 |

**选择 GPT-4o-mini 理由**：成本最低、速度最快、客服场景质量足够。

### 2.3 知识库检索

| 方案 | 复杂度 | 效果 | 适用阶段 |
|------|--------|------|----------|
| 关键词匹配 + TF-IDF | 低 | 基础 | Phase 1（快速上线） |
| pgvector 语义检索 | 中 | 好 | Phase 2（正式版） |
| 专用向量数据库 (Pinecone) | 高 | 最好 | 不采用（增加运维成本） |

**决策**：Phase 1 用关键词匹配快速验证，Phase 2 用 pgvector 升级（复用现有 PG，不增加运维）。

### 2.4 Embedding 模型

| 模型 | 维度 | 成本 | 决策 |
|------|------|------|------|
| text-embedding-3-small | 1536 | $0.02/1M tokens | ✅ 选这个 |
| text-embedding-3-large | 3072 | $0.13/1M tokens | 不需要 |

## 三、数据库设计

### 3.1 知识库表（Phase 2 使用 pgvector）

```sql
-- 需要先安装 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE knowledge_chunks (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category    VARCHAR(50) NOT NULL,      -- 分类：getting-started, ai-trading, ...
  topic_id    VARCHAR(10) NOT NULL,      -- 主题编号：1.1, 2.3, ...
  title_zh    VARCHAR(200) NOT NULL,     -- 中文标题
  title_en    VARCHAR(200) NOT NULL,     -- 英文标题
  content_zh  TEXT NOT NULL,             -- 中文内容
  content_en  TEXT NOT NULL,             -- 英文内容
  keywords    TEXT[] DEFAULT '{}',       -- 关键词标签
  embedding   vector(1536),             -- 文本向量
  metadata    JSONB DEFAULT '{}',        -- 额外元数据
  is_active   BOOLEAN DEFAULT true,
  created_at  TIMESTAMP DEFAULT NOW(),
  updated_at  TIMESTAMP DEFAULT NOW()
);

-- 向量索引（余弦相似度）
CREATE INDEX idx_knowledge_embedding ON knowledge_chunks
  USING ivfflat (embedding vector_cosine_ops) WITH (lists = 10);

-- 分类索引
CREATE INDEX idx_knowledge_category ON knowledge_chunks(category);
```

### 3.2 反馈记录表

```sql
CREATE TABLE support_feedback (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  telegram_id   BIGINT NOT NULL,
  question      TEXT NOT NULL,
  answer        TEXT NOT NULL,
  feedback      VARCHAR(20) NOT NULL,     -- helpful / unhelpful / transfer
  matched_chunks UUID[] DEFAULT '{}',     -- 命中的知识块 ID
  language      VARCHAR(10) DEFAULT 'zh-CN',
  created_at    TIMESTAMP DEFAULT NOW()
);

-- 统计索引
CREATE INDEX idx_feedback_telegram ON support_feedback(telegram_id);
CREATE INDEX idx_feedback_type ON support_feedback(feedback);
CREATE INDEX idx_feedback_date ON support_feedback(created_at);
```

### 3.3 Redis 缓存结构

```
Key:    support:context:{telegramId}
TTL:    1800 (30 分钟)
Value:  JSON {
  "history": [
    { "role": "user", "content": "怎么绑定交易所？" },
    { "role": "assistant", "content": "..." }
  ],
  "firstInteraction": true,          // 是否首次交互（用于显示引导语）
  "unhelpfulCount": 0,               // 连续"没帮助"计数
  "dailyCount": 5,                   // 今日已使用次数
  "language": "zh-CN"
}

Key:    support:daily:{telegramId}:{date}
TTL:    86400 (24 小时)
Value:  问答次数计数器 (INCR)
```

## 五、System Prompt 设计

```
你是 HOOT 平台的 AI 客服助手"圆圆"(YuanYuan)。HOOT 是一个 AI 驱动的非托管量化交易 SaaS 平台。

【角色定位】
- 性格：友善、耐心、专业的理财小助手
- 语气：简洁清晰，适当使用 emoji，不过度使用术语
- 回答长度：3-8 行以内，重要内容 **加粗**

【回答规则】
1. 只回答 HOOT 平台相关问题
2. 基于以下知识库内容回答，不编造信息
3. 不确定时说"这个我不太确定，建议联系人工客服 @hoot_community"
4. 涉及资金安全始终强调"非托管架构，资金在你自己的交易所"
5. 用户情绪激动时先共情再提方案
6. 步骤类问题用数字列表 1. 2. 3.

【严禁内容】
- 不推荐具体币种/交易对
- 不预测价格走势
- 不承诺收益率
- 不讨论竞品
- 不泄露内部信息

【知识库参考】
{retrieved_context}

请用 {language} 回答用户的问题。如果知识库中没有相关信息，诚实地说不确定。
```

## 六、成本估算

### 6.1 LLM 调用成本

| 场景 | 日均量 | tokens/次 | 月成本 |
|------|--------|-----------|--------|
| 问答生成 (GPT-4o-mini) | 500 次 | ~1000 (in+out) | ~$2.25 |
| Embedding (一次性) | 160 段 | ~500/段 | ~$0.002 |
| Embedding (增量更新) | 10 段/周 | ~500/段 | <$0.01 |

**月总成本：约 $2.5**（极低）

### 6.2 基础设施成本

| 组件 | 增量成本 | 说明 |
|------|----------|------|
| PostgreSQL | $0 | 复用现有实例 |
| Redis | $0 | 复用现有实例 |
| pgvector 扩展 | $0 | 开源扩展 |
| Bot 服务器 | $0 | 复用现有 Bot 进程 |

**总增量成本：约 $2.5/月**

### 6.3 用量上限防护

| 限制 | 阈值 | 超限动作 |
|------|------|----------|
| 每用户每日问答 | 20 次 | 提示明日再来 + 引导人工 |
| 单月 LLM 预算 | $10 | 告警 + 降级为关键词匹配 |
| 并发请求 | 10 QPS | 队列排队 |

## 七、分阶段实施计划

### Phase 1：关键词检索 + GPT-4o-mini（1-2 天）

**目标**：最小可用版本上线

1. 从 `help-content.ts` 提取内容，分段为知识库 JSON 文件
2. 实现关键词匹配检索（内存加载、TF-IDF 排序）
3. NestJS 新增 `/api/support/ask` 接口
4. Bot 改造 `message:text` 处理器
5. 添加反馈按钮（👍/👎/📞）
6. Redis 对话上下文缓存

**涉及文件**：
- `apps/telegram-bot/src/index.ts` — 改造消息处理
- `apps/telegram-bot/src/utils/api.ts` — 新增 API 调用
- `apps/api/src/modules/support/` — 新建模块
- `apps/api/src/modules/support/knowledge.json` — 知识库数据

### Phase 2：pgvector 语义检索（1 天）

**目标**：提升检索准确率

1. PostgreSQL 安装 pgvector 扩展
2. 创建 `knowledge_chunks` 表
3. 编写 embedding 生成脚本
4. 替换关键词检索为向量检索
5. 支持语义近似匹配

**涉及文件**：
- `apps/api/prisma/schema.prisma` — 新增 model
- `apps/api/src/modules/support/support.service.ts` — 检索逻辑
- `scripts/embed-knowledge.ts` — embedding 生成脚本

### Phase 3：反馈优化 + 管理看板（持续）

**目标**：数据驱动迭代

1. 创建 `support_feedback` 表
2. 分析高频未命中问题
3. 补充知识库内容
4. 管理后台增加客服数据看板
5. 调优检索阈值和 prompt

## 九、风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| AI 幻觉（编造信息） | System Prompt 限制 + 知识库 context 为主要信息源 + "不确定就说不确定" |
| Prompt 注入/越狱 | 过滤特殊指令词 + System Prompt 安全规则 + 输出审查 |
| 成本失控 | 每用户每日 20 次上限 + 月预算 $10 告警 |
| 知识库过时 | 功能更新时同步更新知识库 + 定期审查 |
| 响应超时 | GPT-4o-mini 通常 1-2s，超 5s 回复"系统繁忙" + 重试 |
| 多语言质量 | 中英文知识库直接使用，其他语言依赖模型翻译能力（需测试验证） |
