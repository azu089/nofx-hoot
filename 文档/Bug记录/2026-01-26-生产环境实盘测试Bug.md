## Bug #1: Freqtrade 服务不可用 (503)

### 现象
- 下载历史 K 线失败："Freqtrade 暂时不可用，请稍后重试"
- 回测失败："无法连接到 Freqtrade: Request failed with status code 503"

### 影响
- 无法进行策略回测
- 无法下载历史 K 线数据
- 阻塞整个策略配置流程

### 根本原因分析

**代码位置**: `apps/api/src/modules/freqtrade/freqtrade.service.ts`

```typescript
// 第 63-172 行
private failedConnections: Map<string, number> = new Map();
private readonly FAIL_CACHE_DURATION = 60000; // 1 分钟内不重试失败的连接
private readonly QUICK_TIMEOUT = 3000; // 快速超时：3 秒

// 快速失败逻辑
if (this.isConnectionFailed(instanceIp)) {
  throw new InternalServerErrorException(
    `Freqtrade 暂时不可用，请稍后重试`,
  );
}
```

**问题**:
1. `QUICK_TIMEOUT = 3秒` 太短，网络波动会导致超时
2. 一旦连接失败，IP 被缓存 60 秒
3. 60 秒内所有请求直接返回 503，即使 Freqtrade 已恢复
4. 没有主动健康检查机制

### 修复方案

1. **增加超时时间**: 将 `QUICK_TIMEOUT` 从 3 秒增加到 10 秒
2. **减少缓存时间**: 将 `FAIL_CACHE_DURATION` 从 60 秒减少到 30 秒
3. **添加重试机制**: 对 503 错误自动重试 1-2 次
4. **健康检查**: 定期清理失败连接缓存

### ✅ 已修复 (2026-01-26)

**修改文件**: `apps/api/src/modules/freqtrade/freqtrade.service.ts`

**修改内容**:
1. `FAIL_CACHE_DURATION`: 60000 → 30000 (30秒)
2. `QUICK_TIMEOUT`: 3000 → 10000 (10秒)
3. 新增 `MAX_RETRIES = 2` 重试机制
4. GET/POST 方法添加自动重试逻辑，4xx 错误不重试

## Bug #2: VPS Token 验证失败

### 现象
- 保存策略配置时报错："策略保存成功但部署失败: VPS 验证失败，Token 无效"

### 影响
- 策略配置保存后无法部署到 VPS
- 用户无法启动策略交易

### 根本原因分析

**代码位置**: `apps/api/src/common/services/network-whitelist.service.ts`

```typescript
// 第 248-279 行
generateInstanceToken(instanceId: string): string {
  const secret = this.configService.get<string>('JWT_SECRET') || 'default-secret';
  return crypto
    .createHmac('sha256', secret)
    .update(`quantfi-instance-${instanceId}`)
    .digest('hex')
    .substring(0, 32);
}

generateFreqtradeToken(instanceId: string): string {
  const secret = this.configService.get<string>('ENCRYPTION_KEY') || 'freqtrade-secret';
  return crypto
    .createHmac('sha256', secret)
    .update(`freqtrade-${instanceId}`)
    .digest('hex')
    .substring(0, 24);
}
```

**问题**:
1. `JWT_SECRET` 和 `ENCRYPTION_KEY` 使用不同的环境变量
2. 如果环境变量未设置，会降级到硬编码的默认值
3. 后端生成的 Token 与 VPS 端期望的 Token 不匹配
4. 可能是生产环境的环境变量配置与 VPS 初始化时不一致

### 修复方案

1. **检查环境变量**: 确认生产环境 `JWT_SECRET` 和 `ENCRYPTION_KEY` 已正确设置
2. **VPS Token 同步**: 重新同步 VPS 实例的 Token
3. **添加日志**: 在 Token 验证失败时打印更详细的信息（期望值 vs 实际值的前几位）

### ✅ 已修复 (2026-01-26) - 添加调试日志

**修改文件**:
1. `apps/api/src/common/services/network-whitelist.service.ts`
2. `apps/api/src/modules/strategies/strategy-deploy.service.ts`

**修改内容**:
1. `generateInstanceToken()`: 添加日志记录 Token 前8位、是否使用默认 Secret
2. `generateFreqtradeToken()`: 添加日志记录 Token 前8位、是否使用默认 Secret
3. `uploadStrategyToVps()`: 添加日志记录发送的 Token 信息
4. 401 错误处理: 增加详细的错误日志，提示检查环境变量

**注意**: 如果日志显示 "使用默认Secret=true"，则需要检查生产环境的环境变量配置！

## Bug #3: VPS 代理服务环境变量未加载 (致命)

### 现象
- VPS Token 验证失败，所有需要 Token 验证的 API 返回 401
- VPS 代理服务无法正确验证请求

### 影响
- 策略部署失败
- 配置更新失败
- VPS 代理服务完全不可用

### 根本原因分析

**代码位置**: `apps/api/src/modules/digitalocean/templates/user-data.sh`

**问题**:
1. PM2 启动 Node.js 服务时，**不会自动加载 `/opt/quantfi/.env` 文件**
2. `process.env.INSTANCE_TOKEN` 为空
3. 所有需要 Token 验证的请求都返回 401

### ✅ 已修复 (2026-01-26)

**修改文件**:
1. `apps/api/src/modules/digitalocean/templates/user-data.sh`
2. `scripts/fix-vps-proxy.sh`

**修改内容**:
在 `server.js` 启动时手动加载 `.env` 文件：

```javascript
const envPath = '/opt/quantfi/.env';
if (fs.existsSync(envPath)) {
  const envContent = fs.readFileSync(envPath, 'utf-8');
  envContent.split('\n').forEach(line => {
    const [key, value] = line.split('=');
    if (key && value && !process.env[key]) {
      process.env[key] = value.trim();
    }
  });
  console.log('✅ 环境变量已从 .env 文件加载');
}
```

## Bug #4: VPS SSH 密码登录被禁用 (致命)

### 现象
- 无法通过统一密码 SSH 登录 VPS
- 错误信息: `Permission denied (publickey)`
- 必须通过 DigitalOcean 控制台访问

### 影响
- 无法远程管理 VPS
- 无法执行修复脚本
- 运维效率极低

### 根本原因分析

**代码位置**: `apps/api/src/modules/digitalocean/templates/user-data.sh` 第 153 行

```bash
# 问题代码（已修复）
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#*PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
```

**问题**:
1. 脚本先设置了 root 密码（第 43 行）
2. 然后禁用了密码登录（第 153 行）
3. 没有添加 SSH 公钥到 authorized_keys
4. SSH 重启后，VPS 完全无法 SSH 登录

### ✅ 已修复 (2026-01-26)

**修改文件**:
1. `apps/api/src/modules/digitalocean/templates/user-data.sh`
2. `apps/api/src/modules/digitalocean/digitalocean.service.ts`
3. `scripts/fix-vps-proxy.sh`

**修改内容**:
1. **启用密码登录**: `PasswordAuthentication yes`
2. **允许 root 登录**: `PermitRootLogin yes`
3. **支持添加 SSH 公钥**: 通过 `MASTER_SSH_KEY` 环境变量
4. **修复脚本**: 增加 SSH 配置修复步骤
