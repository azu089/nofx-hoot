## 二、功能设计方案

### 2.1 P0: 用户资产调整

**位置**: 用户详情页 `/users/[id]` 添加"调整资产"按钮

**交互流程**:
1. 点击"调整资产"按钮
2. 弹出弹窗，显示用户当前各项余额
3. 选择调整类型（增加/扣除）
4. 选择资产类型（USDT/积分/点卡/QFI代币）
5. 输入金额
6. 输入调整原因（必填）
7. 确认执行

**UI 设计**:
```
┌─────────────────────────────────────┐
│         调整用户资产                 │
├─────────────────────────────────────┤
│ 用户: example@email.com             │
│                                     │
│ 当前余额:                           │
│   USDT: 1,234.56                   │
│   积分: 5,000                       │
│   点卡: 10                          │
│   QFI:  0.00                        │
│                                     │
│ 调整类型: ○ 增加  ○ 扣除            │
│                                     │
│ 资产类型: [USDT ▼]                  │
│                                     │
│ 金额: [____________]                │
│                                     │
│ 原因: [________________________]    │
│       (必填，将记入审计日志)         │
│                                     │
│        [取消]      [确认调整]        │
└─────────────────────────────────────┘
```

**API 设计**:
```typescript
// POST /api/admin/users/:id/adjust-balance
{
  "type": "add" | "deduct",
  "assetType": "usdt" | "points" | "cards" | "qfi",
  "amount": "100.00",
  "reason": "活动奖励发放"
}
```

**后端逻辑**:
1. 验证管理员权限
2. 验证用户存在
3. 验证金额合法（扣除时检查余额是否足够）
4. 执行余额变更（事务）
5. 记录审计日志
6. 返回新余额

## 六、风险点

1. **资金安全**: 资产调整功能需要严格的权限控制和审计
2. **并发问题**: 余额变更需要使用事务，防止并发冲突
3. **数据一致性**: 充值审核需要确保余额变更和状态更新的原子性
