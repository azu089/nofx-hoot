## 测试环境准备

### 1. 启动服务

```bash
# 在项目根目录执行
cd /Users/azu/HOOT

# 启动 Docker 服务 (PostgreSQL + Redis)
docker compose up -d

# 验证服务状态
docker compose ps
# 预期: postgres 和 redis 都是 running 状态

# 启动后端 API
cd apps/api
pnpm dev
# 预期: 看到 "Nest application successfully started" 在 4001 端口

# 新终端 - 启动前端
cd apps/web
pnpm dev
# 预期: 看到 "Ready" 在 3001 端口
```

### 2. 数据库准备

```bash
# 在 apps/api 目录
cd /Users/azu/HOOT/apps/api

# 重置数据库（清空所有数据）
pnpm prisma migrate reset --force

# 或仅同步 schema（保留数据）
pnpm prisma db push

# 生成 Prisma Client
pnpm prisma generate
```

## 模块 4: 信号分发与交易执行

### 4.1 模拟 Webhook 信号

> ⚠️ 此测试会触发真实交易！请使用测试网 API Key 或 dry_run 模式

**测试信号发送：**
```bash
curl -X POST http://localhost:4001/api/signals/webhook \
  -H "Content-Type: application/json" \
  -d '{
    "strategy": "RSI_Strategy",
    "symbol": "BTC/USDT",
    "side": "buy",
    "price": "95000"
  }'
```

**验证步骤：**
1. [ ] 信号被接收（检查后端日志）
2. [ ] 信号进入 BullMQ 队列
3. [ ] 订阅用户收到信号
4. [ ] 交易任务创建
5. [ ] 风控检查执行
6. [ ] 交易执行（或模拟执行）
7. [ ] 持仓记录创建

**检查日志：**
```bash
# 后端日志应该显示
# [SignalProcessor] 处理信号分发: xxx buy BTC/USDT
# [SignalProcessor] 找到 X 个订阅用户
# [TradeProcessor] 执行交易任务: 用户 xxx buy BTC/USDT @ 95000
```

### 4.2 多用户同时接收信号

1. 用户 A 和 用户 B 都订阅同一策略
2. 发送一个 Webhook 信号
3. 验证两个用户都收到信号并创建交易任务

## 模块 5: 风控系统

### 5.1 最大持仓数检查

1. 用户订阅策略，maxPositions 设置为 3
2. 连续发送 4 次买入信号
3. 预期：第 4 次被风控拦截

**验证日志：**
```
[RiskControlService] 用户 xxx 已达最大持仓数: 3/3
```

### 5.2 同币种重复持仓检查

1. 发送 BTC/USDT 买入信号（成功开仓）
2. 再次发送 BTC/USDT 买入信号
3. 预期：第 2 次被风控拦截

**验证日志：**
```
[RiskControlService] 用户 xxx 已有 BTC/USDT 持仓
```

### 5.3 每日交易次数限制

1. 连续发送超过 maxDailyTrades (默认 20) 次信号
2. 预期：超过限制后被拦截

### 5.4 余额检查

1. 设置每单金额超过交易所余额
2. 发送信号
3. 预期：被风控拦截，提示余额不足

## 端到端测试流程

### 完整用户流程

```
1. 用户注册/登录
   ↓
2. 添加交易所 API Key
   ↓
3. 浏览策略市场
   ↓
4. 订阅感兴趣的策略
   ↓
5. 等待信号（或手动触发测试信号）
   ↓
6. 收到信号，自动开仓
   ↓
7. 查看持仓，手动平仓
   ↓
8. 查看交易记录和盈亏
   ↓
9. 质押 HOOT 获取分红
   ↓
10. 邀请好友，获取返佣
```

### 多用户并发测试

1. 同时用 2 个浏览器/设备登录不同用户
2. 两个用户订阅同一策略
3. 发送信号，验证两用户同时收到
4. 验证数据隔离（A 看不到 B 的持仓）
