## 一、系统架构概览

### 1.1 信号链流程

```
Freqtrade (dry_run=true)
    │ 策略信号生成
    ▼
POST /signals/webhook (HMAC-SHA256 签名验证)
    │
    ▼
SignalsService.receiveWebhook()
    │ 标准化交易对格式
    │ 解析交易动作: entry_long/exit_long/entry_short/exit_short
    │ 创建 Signal 记录
    ▼
BullMQ 'signal' 队列
    │
    ▼
SignalProcessor (BullMQ Worker)
    │ 查询所有活跃订阅者
    │ 方向过滤 (long/short/both)
    │ 交易对过滤
    │ API Key 有效性检查
    │ 并发锁控制 (Redis Lock)
    ▼
BullMQ 'trade' 队列 (每个用户一个任务)
    │
    ▼
TradeProcessor (BullMQ Worker)
    │ 日亏损限制检查
    │ 黑天鹅保护检查
    │ 完整风控检查
    │ CCXT 执行交易
    │ 持仓监控注册
    │ DCA 补仓注册
    │ 燃油费计算
    │ 推荐返佣处理
    ▼
交易所 (Binance/OKX/Bybit via CCXT)
```

### 1.2 多应用架构

| 应用 | 技术 | 端口 | 说明 |
|------|------|------|------|
| web | Next.js 16 | 3001 | 用户前端 (含管理后台) |
| api | NestJS 10 | 4001 | 后端 API 服务 |
| telegram-bot | NestJS 模块 | - | Telegram Bot 推送 |

## 五、风控系统 (8 大机制)

### 5.1 止盈止损 ✅

| 项目 | 详情 |
|------|------|
| 实现 | PositionMonitorService.checkPnL() |
| 监控周期 | 5 秒 |
| 止盈触发 | PnL >= entryPrice × amount × takeProfitPercent / 100 |
| 止损触发 | PnL <= -(entryPrice × amount × stopLossPercent / 100) |
| 执行方式 | 市价单平仓 |
| 平仓原因 | take_profit / stop_loss |

### 5.2 移动止损 (Trailing Stop) ✅

| 项目 | 详情 |
|------|------|
| 实现 | PositionMonitorService.trackPosition() |
| 监控周期 | 5 秒 |
| 多头激活 | 盈利达到 trailingStopActivation% 后追踪最高价 |
| 空头激活 | 盈利达到 trailingStopActivation% 后追踪最低价 |
| 触发平仓 | 从极值回撤 trailingStopCallback% |
| 执行方式 | 市价单平仓 |
| 平仓原因 | trailing_stop |

### 5.3 最大持仓数限制 ✅

| 项目 | 详情 |
|------|------|
| 实现 | RiskControlService.checkMaxPositions() |
| 默认值 | 5 个 |
| 可配置 | subscription.maxPositions |
| 检查时机 | 每次开仓前 |
| 拒绝原因 | max_positions_reached |

### 5.4 同币种重复持仓检查 ✅

| 项目 | 详情 |
|------|------|
| 实现 | RiskControlService.checkSameSymbol() |
| 规则 | 同币种 + 同方向不可重复开仓 |
| 例外 | 合约模式允许双向持仓 (同时 long + short) |
| 拒绝原因 | symbol_already_open |

### 5.5 日亏损限制 ✅

| 项目 | 详情 |
|------|------|
| 实现 | DailyPnlService.checkDailyLossLimit() |
| 重置 | 每日 UTC 00:00 |
| 计算 | lossPercent = |min(0, realizedPnl + unrealizedPnl)| / startBalance × 100 |
| 触发阈值 | dailyMaxLossPercent (默认 20%) |
| 可选动作 | close_all / close_half / pause |
| 记录表 | daily_settlements |

### 5.6 黑天鹅保护 ✅

| 项目 | 详情 |
|------|------|
| 实现 | MarketMonitorService |
| 监控周期 | 10 秒 |
| 监控币种 | BTC/USDT, ETH/USDT, BNB/USDT, SOL/USDT |
| 价格窗口 | 5 分钟滑动窗口 |
| 两种模式 | coin_drop (币种跌幅) / account_loss (账户亏损) |
| 触发阈值 | blackSwanTrigger (默认 10%) |
| 可选动作 | close_all / close_half / pause |
| 平仓原因 | black_swan |

### 5.7 防瀑布保护 (连亏降仓) ✅

| 项目 | 详情 |
|------|------|
| 关联 | DCA 补仓时检查 |
| 触发 | 总跌幅超过 waterfallTriggerPercent (默认 15%) |
| 效果 | 停止 DCA 补仓 |
| 通知 | waterfall_triggered |

### 5.8 DCA 补仓 (分批建仓) ✅

| 项目 | 详情 |
|------|------|
| 实现 | DcaService.checkDca() |
| 监控周期 | 5 秒 (PositionMonitorService 调用) |
| 触发条件 | 跌幅达到 dcaTrigger% (默认 5%) |
| 补仓金额 | baseAmount × dcaMultiplier^(dcaCount+1) |
| 示例 | 100→150→225→337.5 USDT (1.5 倍率) |
| 最大次数 | dcaMaxCount (默认 3) |
| 新均价 | (原价×旧量 + 现价×新量) / 总量 |
| 风控 | 补仓前执行完整风控检查 |
| 记录表 | dca_logs |

### 5.9 熔断器机制 (Circuit Breaker) ✅

| 项目 | 详情 |
|------|------|
| 实现 | CircuitBreakerService |
| 三态 | closed (正常) → open (故障) → half_open (恢复) |
| 触发条件 | 连续失败 >= 5 次 OR 错误率 >= 50% |
| 冷却时间 | 60 秒 |
| 半开测试 | 允许 3 个请求通过 |
| 持久化 | circuit_breaker_states 表 |
| 管理 | 管理员可手动重置/强制打开 |

| `POST /admin/signals/kill-switch/strategy/:id` | 策略级 Kill Switch |
| `POST /admin/signals/kill-switch/user/:id` | 用户级 Kill Switch |
| `DELETE /admin/signals/kill-switch/global` | 重置全局 Kill Switch |
| `DELETE /admin/signals/kill-switch/strategy/:id` | 重置策略 Kill Switch |
| `DELETE /admin/signals/kill-switch/user/:id` | 重置用户 Kill Switch |

#### Kill Switch 机制
```
全局 Kill Switch:
- 激活 → 所有订阅停止接收信号
- 新信号被拒绝，返回 "global_kill_switch_active"
- 管理员可随时重置

策略级 Kill Switch:
- 激活 → 该策略所有订阅暂停
- 策略信号分发时检查 isKilled 标记

用户级 Kill Switch:
- 激活 → 该用户所有订阅暂停
- 用户信号任务被跳过
```
