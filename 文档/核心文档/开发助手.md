## 0. 文档说明

### 0.1 文档用途

本文档定义了 **PM 只做「通过/打回」决策，AI 负责实现** 的协作模式，包括：
- 技术选型保守主义原则
- 文档即代码要求
- 提交方式与验收标准
- AI 开发禁止事项

### 0.2 与 CLAUDE.md 的关系

- **CLAUDE.md**: 通用技术规范、代码提交规则、验收标准（所有 AI 必读）
- **本文档**: PM 与 AI 协作规则、开发流程约束、决策权限划分

### 0.3 适用角色

- 0 代码 PM / 项目决策者
- 参与本项目的所有 AI 开发助手
- 未来接手项目的新 AI / 新开发者

## 1. 协作核心原则

### 1.1 决策权划分

| 决策类型 | 负责方 | 说明 |
|---------|-------|------|
| 功能需求 | PM | 做什么、不做什么、验收标准 |
| 技术实现 | AI | 怎么做、用什么库、代码怎么写 |
| 架构选型 | PM + AI | AI 提供方案，PM 最终决策 |
| Bug 修复 | AI | AI 负责定位和修复，PM 负责验收 |

**核心规则：**
- PM 只做「通过/打回」，不写代码
- AI 提供完整实现，不做口头承诺
- 有歧义时 AI 先提供 2-3 种方案，PM 选择后再实现

### 1.2 验收标准（Definition of Done）

一次交付完成，必须同时满足：

1. **可用能力**: 本轮只交付 1 个原子任务
2. **肉眼可见成功信号**: 必须能用 curl/Postman/页面 证明功能已生效
3. **验收步骤**: 提供明确的执行步骤 + 预期结果
4. **回滚方案**: 明确如何撤销本次改动
5. **风险与影响说明**: 说明潜在风险点、影响范围

## 2. 技术栈硬约束（QuantFi 专用）

| 类别 | 技术选型 |
|------|---------|
| 语言 | TypeScript |
| 后端 | NestJS |
| 前端 | Next.js 14 (App Router) |
| 包管理 | pnpm (workspace monorepo) |
| 数据库 | PostgreSQL 15 |
| 缓存 | Redis 7 |
| 容器化 | Docker Compose |
| 云服务 | DigitalOcean |
| 对象存储 | S3 |

**严禁在 V1 引入：**
- Kafka / RabbitMQ
- 微服务网关 / Service Mesh
- MongoDB / DynamoDB
- 其他未批准的框架

## 3. 风险分级与审批

| 风险等级 | 操作类型 | 审批要求 |
|---------|---------|---------|
| **高风险** | 删表、改架构、修改鉴权 | 必须 PM 明确批准 |
| **中风险** | 新增依赖、改接口签名 | 需 PM 确认后执行 |
| **低风险** | 新增接口、修 Bug | 正常流程，告知即可 |

### 高风险操作清单

以下操作**必须等 PM 明确说"可以"后才能执行**：

- 删除任何文件或目录
- 修改 `.env` / `docker-compose.yml`
- 引入新的 npm 依赖
- 修改数据库 schema
- 修改用户鉴权/授权逻辑
- 执行 `git push`
- 修改 CI/CD 配置

## 4. QuantFi 业务特殊规则

### 4.1 资金安全

- 所有金额使用 `DECIMAL(18,8)`
- 禁止使用 `FLOAT` 或 `DOUBLE`
- 计费必须幂等（unique_order_id）
- 涉及资金操作必须提供验算脚本

### 4.2 API Key 安全

- 必须 AES-256-GCM 加密存储
- 字段：`encrypted_blob` + `iv` + `auth_tag`
- 严禁日志输出明文
- 仅在容器启动时注入内存环境变量

### 4.3 单租户隔离

- 每个 VIP 用户 = 1 独立 VPS
- 心跳检测：15 分钟无心跳 = 僵尸节点
- 销毁前必须备份到 S3
- 销毁后必须退款

### 4.4 双轨质押

- A 类（空投/积分）：提前解押扣 50% 本金
- B 类（本金购买）：提前解押扣收益 + 3% 手续费
- 权重：A 类固定 1.0x，B 类 1.0x-3.0x 递增
