### 1.8 开源项目下载 - Freqtrade (核心信号引擎) ✅

> **Freqtrade** 是 QuantFi 的信号生成引擎，运行在 `dry_run` 模式生成交易信号，由 NestJS 后端分发给用户

**项目地址**: https://github.com/freqtrade/freqtrade

**下载方式（源码下载）**:

```bash
# 1. 克隆 Freqtrade 源码到项目根目录
git clone https://github.com/freqtrade/freqtrade.git freqtrade

# 2. 进入 Freqtrade 目录
cd freqtrade

# 3. 安装 Python 依赖（需要 Python 3.10+）
python -m pip install --upgrade pip
pip install -e .

# 4. 创建用户数据目录
mkdir -p user_data/{strategies,backtest_results,logs,data}

# 5. 生成默认配置
freqtrade new-config --config user_data/config.json

# 6. 下载示例策略
freqtrade new-strategy --strategy SampleStrategy --strategy-path user_data/strategies

# 7. 回到项目根目录
cd ..
```

## Phase 3: 核心交易系统 MVP (7-10天) ★ 最高优先级

> **目标**：让 2 个用户同时运行策略并执行真实交易
> **验收标准**：用户 A 和用户 B 各自绑定 API Key，订阅同一策略，Freqtrade 发出信号后，两人同时收到并执行交易

### 3.1 MVP 数据库设计 (最小表结构)

```prisma
// ========== MVP 必需表 ==========

// 用户 (最小字段)
model User {
  id            String   @id @default(uuid())
  email         String   @unique
  password      String
  nickname      String?

  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  // 关系
  apiKeys       ApiKey[]
  positions     Position[]
  subscriptions StrategySubscription[]
}

// 交易所 API Key (核心)
model ApiKey {
  id            String   @id @default(uuid())
  userId        String
  user          User     @relation(fields: [userId], references: [id])

  exchange      String   // binance, okx, bybit
  label         String

  // 加密存储 (AES-256-GCM)
  encryptedKey    String
  encryptedSecret String
  iv              String
  authTag         String

  isActive      Boolean  @default(true)
  createdAt     DateTime @default(now())
}

// 策略
model Strategy {
  id            String   @id @default(uuid())
  name          String
  description   String
  freqtradeId   String   @unique  // 对应 Freqtrade 策略名

  isActive      Boolean  @default(true)
  createdAt     DateTime @default(now())

  subscriptions StrategySubscription[]
  signals       Signal[]
}

// 策略订阅 (用户 <-> 策略 多对多)
model StrategySubscription {
  id            String   @id @default(uuid())
  userId        String
  user          User     @relation(fields: [userId], references: [id])
  strategyId    String
  strategy      Strategy @relation(fields: [strategyId], references: [id])

  // 用户配置
  apiKeyId        String   // 使用哪个 API Key
  amountPerTrade  Decimal  @db.Decimal(18, 8)  // 每单金额
  maxPositions    Int      @default(3)

  isActive      Boolean  @default(true)
  createdAt     DateTime @default(now())

  @@unique([userId, strategyId])
}

// 交易信号 (从 Freqtrade 接收)
model Signal {
  id            String   @id @default(uuid())
  strategyId    String
  strategy      Strategy @relation(fields: [strategyId], references: [id])

  symbol        String   // BTC/USDT
  side          String   // buy, sell
  price         Decimal  @db.Decimal(18, 8)

  // 信号分发追踪
  distributedAt DateTime?

  createdAt     DateTime @default(now())
}

// 持仓
model Position {
  id            String   @id @default(uuid())
  userId        String
  user          User     @relation(fields: [userId], references: [id])

  exchange      String
  symbol        String
  side          String   // long, short

  entryPrice    Decimal  @db.Decimal(18, 8)
  amount        Decimal  @db.Decimal(18, 8)

  // 交易所返回的订单ID
  exchangeOrderId String?

  status        String   @default("open") // open, closed, failed
  closedAt      DateTime?
  closePrice    Decimal? @db.Decimal(18, 8)
  pnl           Decimal? @db.Decimal(18, 8)

  signalId      String?

  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
}
```

#### 3.2.6 交易执行 (2天) ⭐ 核心

> **架构说明**：Freqtrade 底层用的就是 CCXT，我们不需要复制 Freqtrade 代码，
> 而是**直接利用 CCXT 已有的能力**处理交易细节（精度、最小量、余额等）。

**CCXT 内置能力（直接使用，无需自己实现）**：

| 功能 | CCXT 方法 | 说明 |
|------|-----------|------|
| 数量精度 | `exchange.amountToPrecision(symbol, amount)` | 自动处理小数位 |
| 价格精度 | `exchange.priceToPrecision(symbol, price)` | 自动处理价格精度 |
| 最小下单量 | `exchange.markets[symbol].limits.amount.min` | 获取最小下单量 |
| 余额查询 | `exchange.fetchBalance()` | 获取可用余额 |
| 市场信息 | `exchange.loadMarkets()` | 加载交易对信息 |

**示例代码（利用 CCXT 内置能力）**：

```typescript
// 使用 CCXT 的内置方法处理精度和限制
async function executeOrder(exchange: ccxt.Exchange, symbol: string, side: string, amount: number) {
  // 1. 加载市场信息（CCXT 自动缓存）
  await exchange.loadMarkets();

  // 2. 检查最小下单量（CCXT 提供）
  const minAmount = exchange.markets[symbol].limits.amount.min;
  if (amount < minAmount) {
    throw new Error(`下单量 ${amount} 低于最小值 ${minAmount}`);
  }

  // 3. 精度处理（CCXT 内置方法）
  const preciseAmount = exchange.amountToPrecision(symbol, amount);

  // 4. 创建订单
  const order = await exchange.createMarketOrder(symbol, side, preciseAmount);

  return order;
}
```

### 3.3 MVP 数据流

```
┌─────────────────────────────────────────────────────────────┐
│                      MVP 核心数据流                          │
│                                                             │
│   架构核心：Freqtrade (信号) → NestJS + CCXT (执行)          │
│   关键点：CCXT 已内置精度处理、最小量检查、余额查询等功能     │
└─────────────────────────────────────────────────────────────┘

  Freqtrade (dry_run 模式)
       │
       │ Webhook (买入/卖出信号)
       │ 只负责策略判断，不做真实交易
       ▼
  ┌─────────────┐
  │ NestJS API  │ POST /signals/webhook
  │  信号接收   │
  └─────┬───────┘
        │
        ▼
  ┌─────────────┐
  │  BullMQ     │ signal-queue
  │  信号队列   │
  └─────┬───────┘
        │
        ▼
  ┌─────────────┐     查询订阅用户
  │ 信号处理器  │ ──────────────────► 用户 A (订阅策略 X)
  │ SignalProc  │ ──────────────────► 用户 B (订阅策略 X)
  └─────┬───────┘
        │
        │ 为每个用户创建交易任务
        ▼
  ┌─────────────┐
  │  BullMQ     │ trade-queue
  │  交易队列   │
  └─────┬───────┘
        │
        ▼
  ┌───────────────────────────────────────────────────────┐
  │ 交易处理器 (TradeProcessor)                            │
  │                                                       │
  │  1. 解密用户 API Key                                   │
  │  2. 使用 CCXT 内置方法：                               │
  │     - fetchBalance()        → 余额检查                │
  │     - markets[symbol].limits → 最小下单量检查          │
  │     - amountToPrecision()   → 数量精度处理            │
  │     - priceToPrecision()    → 价格精度处理            │
  │  3. 执行订单                                          │
  │     - createMarketOrder() / createLimitOrder()        │
  └───────────────────────────────────────────────────────┘
        │
        │ CCXT 统一接口下单
        ▼
  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
  │  Binance    │     │    OKX      │     │   Bybit     │
  │  用户 A     │     │   用户 B    │     │   用户 C    │
  └─────────────┘     └─────────────┘     └─────────────┘
```

### 3.3.1 架构要点

| 组件 | 职责 | 不做什么 |
|------|------|---------|
| **Freqtrade** | 运行策略、生成买卖信号 | 不做真实交易 (dry_run) |
| **NestJS** | 接收信号、用户管理、订阅管理、任务调度 | 不复制 Freqtrade 代码 |
| **CCXT** | 交易执行、精度处理、余额查询、订单管理 | - |
| **BullMQ** | 异步任务队列、失败重试 | - |

> **重要**：所有交易细节（精度、最小量、余额等）由 CCXT 处理，
> 我们不需要自己实现这些逻辑，直接调用 CCXT 内置方法即可。
