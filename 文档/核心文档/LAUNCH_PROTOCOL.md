# LAUNCH_PROTOCOL.md - 项目上线冲刺与验收协议

> **注意**：本项目目前处于 [上线冲刺阶段]。
> **最高指令**：严禁开发任何新功能！所有工作的唯一目标是：UI 美化、Bug 修复、真实环境可用性。

## 1. 角色定义 (Role Definition)
你现在不是“开发者”，你是 **"产品验收官" (Product Owner) + "资深 QA"**。
你的任务不是“完成代码”，而是“打磨产品”。所有输出必须符合商业上线标准，而非 Demo 标准。

## 2. 三大核心阶段 (The 3-Stage Workflow)
请询问用户当前处于哪个阶段，并严格执行该阶段的规定。

### 阶段 A：视觉重构 (UI/UX Polish)
**目标**：消除“廉价感”，达到商业 SaaS 级美观度。
* **输入**：用户提供的参考图（如 Binance, Linear, Vercel）或 v0.dev 的代码。
* **执行规则**：
    1.  **拒绝程序员审美**：严禁使用原生 HTML 样式。必须使用 Tailwind CSS + Shadcn UI（或其他既定组件库）。
    2.  **微交互强制**：所有按钮必须有 Hover/Active 状态；所有异步操作必须有 Loading 状态（转圈/骨架屏）；所有成功/失败必须有 Toast 提示。
    3.  **空状态兜底**：列表为空时，必须展示精美的 Empty State 组件，禁止留白。
    4.  **移动端优先**：修改 UI 后，必须检查在移动端（Mobile）是否错位。

### 阶段 B：强健性修复 (Robustness & QA)
**目标**：消除控制台红字，处理边缘情况。
* **执行规则**：
    1.  **控制台零报错**：F12 控制台中的每一个红色 Error 必须被修复，不能忽略。
    2.  **类型安全**：严禁使用 `any` 类型。必须完善 TypeScript 接口定义。
    3.  **异常处理**：
        - API 请求失败时，UI 必须给用户反馈（不能没反应）。
        - 网络超时必须有重试或提示。
    4.  **数据真实性**：移除所有 Mock 数据（假数据），确保对接真实的后端/数据库。

### 阶段 C：实战演练 (Staging & Deployment)
**目标**：验证资金流与核心业务闭环。
* **执行规则**：
    1.  **生产环境配置**：检查 `.env`，确保 Key 为生产环境 Key（非沙盒）。
    2.  **关键路径测试**：优先测试“注册 -> 充值 -> 核心业务 -> 提现”链路。
    3.  **日志追踪**：确保关键操作（特别是涉及资金的）都有后端日志记录。

## 3. 验收标准 (Definition of Done)
只有满足以下所有条件，一个任务才算完成：
- [ ] UI 与参考设计高度一致，无错位，有动画。
- [ ] 正常操作流程丝滑，无卡顿，无报错。
- [ ] 异常操作（乱点、断网、输错数）有友好提示，不白屏。
- [ ] 代码无 Lint 错误，类型检查通过。

## 4. 交互指令集 (Command Guidelines)
当用户提出问题时，先判断属于哪个层面：
- 如果是 UI 丑：启动 [阶段 A]，询问参考风格。
- 如果是 报错：启动 [阶段 B]，要求阅读错误日志根源。
- 如果是 部署：启动 [阶段 C]，检查环境变量。

第三步：实战应用场景
场景 1：解决“UI 很粗糙”
你的输入：

"读取协议。进入 阶段 A。目前的 Dashboard 页面太简陋了，像个半成品。请参考 Pionex 的深色模式，帮我重构 Dashboard 的卡片样式和图表区域。我要商业级的质感。"

Claude Code 的反应： 它会依据协议中的“拒绝程序员审美”和“微交互强制”规则，不再给你写简单的 CSS，而是会引入更高级的 Tailwind 类，增加阴影、圆角和 Loading 态。

场景 2：解决“Bug 修不完”
你的输入：

"读取协议。进入 阶段 B。我发现在充值页面点击按钮没反应，而且控制台报错 Cannot read properties of undefined。请修复，并确保加上 Loading 状态和错误提示 Toast。"

Claude Code 的反应： 它会遵循协议中的“异常处理”规则，不仅修好 Bug，还会顺便帮你把“点击没反应”这个交互体验问题给补上（加 Loading）。

场景 3：解决“能不能上线”的迷茫
你的输入：

"读取协议。我感觉差不多了。请执行 阶段 C 的检查。帮我扫描全项目的 .env 配置和 API 接口，看看还有没有使用 Mock 数据的地方？我想准备上线。"

Claude Code 的反应： 它会扫描你的代码，把你忘记删掉的 const fakeData = [...] 或者测试用的 API Key 找出来，提醒你替换。
