## 第一部分：战略定位与商业全景 (Strategic Overview)

### 1.1 项目定义

QuantFi 是一个基于开源 Freqtrade 引擎深度构建的 Web3 量化 SaaS 平台。它通过"单租户隔离"技术解决小白用户的量化门槛问题，并结合 GameFi 代币经济模型，将单纯的"付费工具"转化为具备"资产增值"属性的生态系统。

### 1.2 商业模式 (Business Model)

采用 **Real Yield (真实收益)** 飞轮模型：

1. **SaaS 订阅 (Cash Flow)**：用户支付月费（如 $25/月），覆盖 VPS 成本（约 $5/月），剩余为刚性利润。
2. **燃油费/抽成 (Gas Fee)**：从用户盈利中抽取 20%（以预充值点卡形式扣除）。这是平台核心利润来源。
3. **资产增值 (Asset Value)**：平台收入的 40% 用于回购销毁或分红，推高 $QFI 代币价值。

### 1.3 目标形态 (Product Form)

* **Web 端 / PWA**：全功能大本营（策略、资金、质押、后台）。
* **Telegram Mini App**：裂变与轻量化入口（查看收益、签到、邀请）。
* **App Store/Google Play (特洛伊木马策略)**：阉割版"数据看板"，仅做行情与状态监控，引流至 Web 端成交，规避 30% 税与合规风险。

## 第二部分：技术架构与底层设计 (Technical Architecture)

### 2.1 物理架构：单租户隔离 (Single-Tenant Isolation)

* **核心原则**：1 VIP 用户 = 1 独立 DigitalOcean Droplet (VPS)。
* **管理中枢 (Master)**：运行 Web/API/DB/Redis。
* **工作节点 (Workers)**：
  * **动态编排**：通过 Cloud-Init (User Data) 脚本实现全自动开机、装 Docker、跑策略。
  * **生命周期**：用户付费即创建，欠费/停止即销毁 (Destroy) 以节省成本。
  * **IP 独立**：每位用户拥有独立公网 IP，彻底规避交易所连坐封禁风险。

* **数据灾备**：
  * **持久化**：VPS 销毁前，自动打包 `trades.sqlite` 和 `config.json` 上传至 S3 对象存储。
  * **恢复**：新 VPS 启动时自动下载恢复，实现"无感迁移"。

### 2.2 核心引擎 (Core Engine)

* **内核**：Freqtrade (Python) 容器化运行。
* **AI 赋能**：
  * **AI 策略生成器**：前端集成 OpenAI GPT-4，支持自然语言生成完整 Freqtrade 策略代码（如"RSI<30买入"），包含指标计算、入场出场逻辑、止损止盈参数。
  * **AI 持仓解读（智能投顾）**：[2026-01-10 已实现]
    * **技术架构**：采用 DeepSeek V3 (cost-efficient) + OpenAI (account-level) 双模型架构
    * **核心功能**：
      - 单笔持仓实时解读：基于开仓价、当前盈亏、持仓时长等数据，提供触发信号、趋势判断、执行动作、核心解读四维分析
      - 专业金融分析风格：避免口语化表达，采用客观、技术化的投顾语言
      - 智能缓存机制：1小时内相同持仓使用缓存结果，大幅降低 API 调用成本
      - 降级容错：DeepSeek API 失败自动降级到高质量模拟数据，保证用户体验不中断
    * **成本控制**：
      - DeepSeek V3: $0.27/1M tokens，单次调用约 $0.000135（极低成本）
      - 1小时缓存 + 数据库持久化，实际成本降低 60%+
      - VIP 等级配额管理：普通用户不限制（interpretation 类型），策略生成受配额限制
    * **实现细节**：
      - 后端接口：`POST /api/ai/interpret-trade`（需 JWT 认证）
      - 请求参数：pair(交易对), side(方向), amount(数量), price(开仓价), pnl(盈亏), executed_at(时间)
      - 响应数据：trigger(触发信号), trend(趋势判断), action(执行动作), explanation(核心解读), sentiment(市场情绪)
      - 缓存键：`interpret:${pair}:${price}:${pnl}`，存储在 ai_generations 表
    * **前端集成**：
      - 持仓卡片组件：点击"AI 解读"按钮触发分析
      - 渐进式展示：加载态 → 解读结果（人话总结 + 技术详情）
      - 视觉设计：使用渐变背景 + 情绪色彩（盈利绿色/亏损红色）增强可读性
    * **技术文件**：
      - `apps/api/src/modules/ai/ai.service.ts`: 核心 AI 服务逻辑（600+ 行）
      - `apps/api/src/modules/ai/ai.controller.ts`: RESTful 接口层
      - `apps/api/src/modules/ai/dto/generate-strategy.dto.ts`: 数据传输对象定义
      - `apps/web/src/components/features/trading/PositionCard.tsx`: 前端持仓卡片组件
    * **后续优化方向**：
      - Redis 缓存迁移（提升访问速度 10-100 倍）
      - 策略类型识别（RSI/MACD/网格/套利等差异化 Prompt）
      - 实时市场数据增强（集成 K 线、成交量、RSI 等技术指标）
      - 日志监控与成本统计（Prometheus 指标 + 告警系统）
  * **AI 账户分析**：批量交易记录分析，提供胜率、风险评分、优化建议（使用 OpenAI GPT-4o-mini）。

### 2.3 安全堡垒 (Security Fortress)

* **API Key 托管**：
  * AES-256-GCM 加密存储于数据库。
  * 仅在 Docker 启动瞬间注入内存环境变量，严禁明文落地。

* **网络风控**：VPS 仅开放 SSH（白名单 IP）和 API 端口（内网/鉴权），拒绝公网扫描。

* **设备指纹反作弊**：检测同设备多账号注册，防止薅羊毛。

## 第三部分：代币经济模型 (Tokenomics - The Real Yield)

### 3.1 双资产体系

1. **Q-Points (积分/链下)**：无限增发，用于抵扣订阅费、兑换代币。获取方式：交易挖矿、返佣。
2. **$QFI (代币/链上)**：ERC-20 标准，总量 1 亿枚，通缩模型。

### 3.2 收入分配飞轮

平台总收入（USDT）分配：

* **40%**：运营成本（服务器、API、人力）。
* **40%**：回购奖励池（智能合约自动在 DEX 回购 $QFI）。
  * 50% -> 销毁 (Burn)。
  * 50% -> 分发给质押者 (Yield)。
* **20%**：风险储备金（冷钱包托底）。

### 3.3 质押系统 (Dual-Track Staking)

引入 veToken 权重模型：

| 质押类型 | 资金来源 | 提前解押惩罚 (Penalty) | 权重乘数 |
| :--- | :--- | :--- | :--- |
| **A 类：空投/积分** | 活动赠送/挖矿 | 扣除 50% 本金 (销毁) | 1.0x |
| **B 类：本金购买** | USDT 购买 | 不扣本金，仅扣累计收益 + 3% 手续费 | 1.0x - 3.0x (随时间递增) |

### 3.4 释放与兑换 (Vesting)

* **基于订单隔离**：每笔兑换独立计算释放期。
* **标准模式**：20% 立即释放 + 80% 在 90 天内线性释放。
* **急速模式**：立即获得 50%，剩余 50% 直接销毁，订单结束。

## 第五部分：全流程风控与容错机制 (Risk Management)

### 5.1 开发阶段风控 (Dev Phase)

* **沙盒模拟**：所有涉及 DigitalOcean 扣费的操作，必须先在 Mock 环境跑通。
* **强类型约束**：后端 NestJS + 前端 TypeScript，杜绝数据结构错误。
* **原子化任务**：遵循 CLAUDE.md，每一步必须有验算脚本。

### 5.2 运行阶段风控 (Runtime Phase)

* **计费幂等性**：数据库 `billing_logs` 设置 `unique_order_id` 索引，物理杜绝重复扣费。
* **双向心跳熔断**：主控服 15 分钟未收到 VPS 心跳 -> 判定僵尸节点 -> 强制销毁 -> 退款 -> 报警。
* **Docker 自愈**：配置 `restart: always` 及内部 Watchdog 脚本，进程死锁自动重启。
* **极端行情保护 (Kill Switch)**：管理员后台红色按钮 -> 全网并发调用 `/stopbuy` -> 停止开单/紧急平仓。

### 5.3 业务与法律风控 (Legal & Business)

* **文案伪装**：分红 -> 协议收入；代客理财 -> 技术服务费。
* **用户协议 (ToS)**：注册必勾选"本平台仅提供工具，不承担策略运行风险"。
* **反作弊**：同 IP/设备指纹关联账号限制。

  * **实时结算**：用户使用策略产生盈利后，每笔燃油费立即分成给策略创作者，从平台运营成本扣除。

## 第九部分：技术实现日志 (Implementation Log)

### 9.1 AI 持仓解读功能实现 (2026-01-10)

#### 背景
用户在查看实时持仓时，需要理解每笔交易的触发逻辑、市场趋势和当前状态，但技术指标和策略逻辑对非专业用户门槛较高。

#### 解决方案
实现基于 AI 大模型的单笔持仓智能解读功能，将复杂的技术分析转化为易懂的专业投顾语言。

#### 技术选型
| 组件 | 选择 | 理由 |
|------|------|------|
| 单笔持仓解读 | DeepSeek V3 | 成本极低（$0.27/1M tokens），质量接近 GPT-4，适合高频调用 |
| 账户级分析 | OpenAI GPT-4o-mini | 低频深度分析，需要更强推理能力 |
| 策略生成 | OpenAI GPT-4 | 需要生成可执行代码，对准确性要求高 |

#### 实现架构
```
用户点击 "AI 解读"
    ↓
前端 PositionCard 组件
    ↓
POST /api/ai/interpret-trade (JWT 认证)
    ↓
AiService.interpretTrade()
    ↓
1. 检查缓存（ai_generations 表，1小时有效）
    ↓ (缓存未命中)
2. 调用 DeepSeek V3 API
    - model: deepseek-chat
    - temperature: 0.7
    - max_tokens: 800
    - 专业投顾 System Prompt
    ↓ (API 调用失败)
3. 降级到高质量模拟数据
    ↓
4. 返回解读结果 + 缓存存储
    ↓
前端渲染：人话总结 + 技术详情 + 情绪色彩
```

#### 核心代码文件
| 文件路径 | 说明 | 代码量 |
|---------|------|--------|
| `apps/api/src/modules/ai/ai.service.ts` | AI 服务核心逻辑，含 DeepSeek 集成 | +165 行 |

| **总计** | **6 个文件** | **+235 行** |

#### 数据结构
**请求参数** (`InterpretTradeDto`):
```typescript
{
  pair: string;          // 交易对，如 "BTC/USDT"
  side: string;          // 方向：buy/sell
  amount: string;        // 持仓数量
  price: string;         // 开仓价格
  pnl: string;           // 浮动盈亏（USDT）
  executed_at: string;   // 开仓时间（ISO 格式）
}
```

**响应数据**:
```typescript

  trigger: string;       // 触发信号（如：RSI 指标触发超卖信号）
  trend: string;         // 趋势判断（如：市场趋势符合策略预期）
  action: string;        // 执行动作（如：以 $65,000 市价买入 0.0015 BTC）
  explanation: string;   // 核心解读（80-120字专业总结）
  sentiment: 'bullish' | 'bearish' | 'neutral';  // 市场情绪
}
```

#### System Prompt 设计
```
你是一位专业的量化交易分析师，擅长解读加密货币交易信号和持仓逻辑。

你的任务是为用户解读单笔持仓背后的交易逻辑，包括：
1. 触发信号：基于技术指标分析为什么策略会在这个价位开仓
2. 趋势判断：分析当前市场趋势是否符合策略预期
3. 执行动作：说明具体的开仓操作细节
4. 核心解读：用专业但易懂的语言总结这笔持仓的核心逻辑和当前状态

风格要求：
- 专业、客观、基于技术分析
- 语言简洁、直接、易懂
- 避免过于口语化的表达（如"老板"等）
- 关注技术指标和市场信号
- 提供可操作的观察建议
```

#### 容错与降级
1. **API 调用失败**：自动降级到高质量模拟数据，保证 100% 可用性
2. **缓存失效**：即使数据库查询失败，也能正常生成解读
3. **网络超时**：DeepSeek API 超时后立即返回模拟数据，不阻塞用户
4. **配额耗尽**：当 DeepSeek API Key 额度用尽时，自动切换到模拟模式

   - 然后展示技术详情（触发信号、趋势分析、执行操作）
3. **视觉设计**：
   - 使用渐变背景（brand-primary/5 to brand-secondary/5）
   - 盈利用绿色主题，亏损用红色主题
   - 图标辅助理解（TrendingUp/TrendingDown/Activity/Zap/Target）
4. **交互优化**：
   - 缓存结果，再次点击直接展开/收起，无需重新加载
   - 展开动画：fade-in + slide-in-from-top

#### 风险与限制
1. **DeepSeek API 依赖**：如 DeepSeek 服务中断，自动降级到模拟模式，不影响用户使用
2. **成本控制**：虽然单次成本极低，但大规模使用需持续监控（已实现 tokens_used 记录）
3. **解读准确性**：AI 生成内容基于 Prompt 指导，可能存在误判，需持续优化 Prompt
4. **数据隐私**：持仓数据发送到 DeepSeek API，需确保符合隐私政策（数据已脱敏）

#### 关键设计决策
1. **为什么选择 DeepSeek V3**：成本仅为 GPT-4 的 1/10，质量接近，适合高频场景
2. **为什么使用 1 小时缓存**：平衡实时性和成本，用户多次查看同一持仓时避免重复调用
3. **为什么不限制配额**：持仓解读是核心用户体验功能，限制会严重影响满意度
4. **为什么保留模拟数据**：保证 100% 可用性，即使 API 失败也能提供合理解读
5. **为什么使用数据库缓存**：PostgreSQL 已有 ai_generations 表，无需额外引入 Redis（Phase 2 再优化）
